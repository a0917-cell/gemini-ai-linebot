# Spec：Gemini AI bot → 個人助手

2026-09-29 · 狀態：已定案，進 /plan

## 1. 問題

這個 bot 目前只會「對自己上傳的文件做 RAG 查詢」。實測有三個狀況：
- 冷啟動 42.5 秒（Render 免費方案休眠，6 月設的保溫已失效），超過 LINE 的回應時限，第一則訊息常常沒回。
- 預覽版模型 `gemini-3-flash-preview` 過載時，直接把 `503 UNAVAILABLE` 原文丟給使用者。
- 沒有提醒功能；問法規時，也只能靠模型自己的記憶回答。

不處理的話，它只能當一個偶爾會回的文件搜尋器，當不了助手。

## 2. 目標 / 非目標

**目標**
1. 一般問答與寫作（含中越日翻譯）：沒有相關文件時，照樣直接回答。
2. 查使用者自己上傳的資料：沿用現有的 File Search 設計與 `user_id` 隔離。
3. 工作專業問答：台灣建築法規、施工計畫、BIM。HJPLUS 知識庫的法規條文放進同一個 store，所有人共用，回答時標出條文出處。
4. 提醒：「明天 9 點提醒我繳圖」→ 時間到了 push 訊息，重啟、休眠後也不會遺失。
5. 穩定性：用正式版模型，過載時先重試，再改用備援模型，使用者看到的是中文說明，不會看到原始錯誤。

**非目標**
- 不讀使用者電腦上的檔案，也不自動同步 Drive（資料來源＝在 LINE 傳檔）。
- 不做群組功能，只處理一對一聊天。
- 不換掉 File Search，不自建向量資料庫（沿用原有決策 #1）。
- 不改用付費模型，不升級 Render 方案。
- 不做重複提醒（每週、每月）。v1 只做單次提醒。
- 不做對話記憶。v1 每則訊息各自獨立。

## 3. 使用者看到的行為

| 輸入 | 輸出 |
|---|---|
| 「幫我把這段改得正式一點：…」 | 直接改寫，不去查文件 |
| 「上次傳的帷幕送審單審查意見是什麼？」 | 根據使用者上傳的文件回答，附上文件名稱 |
| 「防火區劃面積上限？」 | 依法規條文回答，附「出處：建築技術規則 第 79 條」；引用的 KB 內容只要有一份不是標 `verified`（包括沒標的）就加註「待查證」 |
| 「明天 9 點提醒我繳圖」 | 回「⏰ 已設定：9/30（二）09:00 繳圖」；時間到了 push「⏰ 提醒：繳圖」 |
| 「提醒我」（沒給時間） | 反問「要在什麼時間提醒？」，不會隨便猜一個時間 |
| 「昨天 9 點提醒我…」（過去的時間） | 回「這個時間已經過了」，不建立提醒 |
| 「我的提醒」 | 列出還沒到的提醒，每筆都可以取消 |
| 模型過載，重試和備援都失敗 | 「⚠️ AI 忙線中，請 1 分鐘後再傳一次」 |
| 空白訊息、貼圖 | 不回應（跟現在一樣） |

## 4. 驗收條件

1. 設定的 `GEMINI_MODEL` 是非 preview 的正式版 id，備援模型 id 另外設定；單元測試模擬主模型回 503，確認最後走到備援模型。
2. 主模型和備援模型都失敗時，回覆文字不含 `503`、`{'error'` 這類原始錯誤字串（單元測試）。
3. 使用者沒上傳任何文件時問「台北今天適合做什麼」，得到直接回答，不是「查無資料」（手動 10 秒）。
4. 使用者 A 上傳的文件，使用者 B 查不到（沿用現有的 metadata filter，加一條回歸測試）。
5. 法規題的回答帶有條文出處；查詢時的 filter 是「`user_id=本人` 或 共用 KB」（單元測試檢查 filter 字串）。
6. 設定提醒後重新部署，提醒仍然存在，並在設定時間 ±5 分鐘內 push（手動測一次，時間設在 10 分鐘後）。
7. 過去的時間、缺少時間這兩種輸入，都不會建立提醒（單元測試）。
8. 閒置 1 小時後傳訊息，30 秒內收到回覆（手動測一次）。

## 5. 決定（2026-09-29 使用者確認「照建議」）

1. **提醒**：存在 Google Sheets（沿用 line-archiver-bot 的 OAuth 寫法），由 UptimeRobot 每 5 分鐘 GET `/cron/tick` 觸發，同時負責保溫。tick 端點要驗證一個密鑰參數，不然任何人都能觸發。
2. **HJPLUS**：只放 `raw\` 裡的法規條文與方法論，以 `scope=kb` 標記、所有人共用。建索引前先查官方文件確認 File Search 免費方案的上限與費用；會花錢就先停下來問。
3. **對話記憶**：v1 不做（列入非目標），第二版再評估。
